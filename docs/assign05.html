Assignment 5

Introduction

This assignment uses the GovInfo API to collect congressional hearing documents and examine how government data can be accessed programmatically. I focus on hearings of the Senate Committee on Foreign Relations and compare the results from the GovInfo search interface with those returned by the API.

The main distinction is between finding documents and making their contents usable as data. Although the API provides structured metadata and direct links to different document formats, the availability of a downloadable file does not necessarily mean that its contents can be analyzed without further processing.

1. Searching GovInfo manually

Before using the API, I searched the GovInfo search page for hearings of the Senate Committee on Foreign Relations. I sorted the results by publication date, with the newest documents first, and exported the results for comparison with the API.

I saved the website export locally. I also recorded the query generated by the search page.

Search details

  • Search page: GovInfo

  • Collection: Congressional Hearings

  • Committee: Senate Committee on Foreign Relations

  • Sort order: Publication date, newest first

  • Query generated by the website

The website export will serve as the reference list for checking whether the API returns the same ten hearings.

3.3. Downloading the ten PDFs

The following function retrieves the PDF link from each package summary, downloads the file, and records whether the download succeeded. It also records errors so that failed requests can be investigated rather than silently ignored.

I was having trupiuble downloading the PDFs because they didn’t seem to be available as easily as the manual, hence I downloaded the zip fails which include the PDFs.

get_zip_link <- function(summary) {
  links <- summary$download
  
  if (is.null(links) || is.null(links$zipLink)) {
    return(NA_character_)
  }
  
  links$zipLink
}

download_hearing <- function(package_id, title) {
  tryCatch({
    summary <- get_package_summary(package_id)
    zip_url <- get_zip_link(summary)
    
    if (is.na(zip_url) || !nzchar(zip_url)) {
      stop("No ZIP link was available.")
    }
    
    # Append the API key to the ZIP URL
    zip_url <- paste0(
      zip_url,
      if (grepl("\\?", zip_url)) "&" else "?",
      "api_key=",
      api_key
    )
    
    file_path <- file.path(
      download_dir,
      paste0(package_id, ".zip")
    )
    
    request(zip_url) |>
      req_perform(path = file_path)
    
    tibble(
      packageId = package_id,
      title = title,
      file = file_path,
      status = "success",
      error = NA_character_
    )
  }, error = function(e) {
    tibble(
      packageId = package_id,
      title = title,
      file = NA_character_,
      status = "failed",
      error = conditionMessage(e)
    )
  })
}

4. Report

Difficulties with the collection process

One of the main difficulties was figuring out how to get from the search results to the actual documents. The GovInfo website makes it possible to search and export records, but I still needed to make sure that the results corresponded to the hearings I was looking for. With the API, I could retrieve the records in R and sort them by publication date, but I had to understand how the search query worked and how the information was organized in the API response.

Downloading the documents was another challenge. I initially tried to retrieve PDF links from the package summaries, but the response did not include a direct PDF link. Instead, it provided a ZIP download link, so I changed my code to download the hearing packages as ZIP files. This also showed me that keeping a download log matters since finding a document through the API does not necessarily mean that the file has been downloaded successfully.

a. How usable are the downloaded documents as data?

The hearing documents contain useful information, but the PDFs are not ready to analyze directly. To turn them into a table or text corpus, I would first need to extract the text and organize it into a consistent format. For example, I could record the hearing date, title, speaker, and statements made during the hearing. I would also need to check the extracted text for formatting problems, since tables, speaker labels, and other document elements might not be captured correctly.

b. How could the process be improved?

I could make the process more efficient by using the other formats available through GovInfo instead of relying on PDFs alone. Plain-text files would be easier to work with for text analysis, while the metadata already provides information such as the title, date, chamber, and document type. This information could be collected before opening or processing the documents and used to organize the dataset. I would also keep the search query and download log so that I could check which documents were collected and reproduce the process later.

c. What did the API provide that the search page and last week’s scraping did not?

The API allowed me to retrieve structured search results directly in R, which made it easier to filter, sort, and compare documents without manually processing a webpage. It also provided access to package metadata and download links, making it easier to collect information about multiple documents in a more consistent and reproducible way. It is also a more reliable and legal/ethical way of obtaining data. There is not many hurdles to get through after being authorized an API key, whereas for scraping we had to politely get the info.
